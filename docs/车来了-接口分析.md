# 「车来了」App 接口分析

> 分析对象：工作区中的 `车来了.apk`。本文所有结论来自静态反编译，未实际调用线上接口。
> 反编译源码：`jadx_c6/`（业务代码，`classes6.dex`）；解包数据：`apk_extract/`。

## 1. 总体架构

App 本身不接收公交车定位信号，而是向服务端查询：

1. 用户选定线路与等车站，App 发送 `lineId + targetOrder + 本机位置 + 公共参数`。
2. 服务端返回该线路上每辆车的实时状态（站点序号、经纬度、预计到站时间）。
3. App 解密响应，在客户端计算「还有几站」「还有多少米」，并展示服务端给出的「还有几分钟」。
4. 默认每 30 秒轮询刷新，服务端可通过响应字段修改刷新间隔。

公交车定位的上游来源（车载 GPS、公交公司调度系统等）属于服务端内部，无法从 APK 中确认。

- 主域：`https://api.chelaile.net.cn`
- 备域：`https://cdn.api.chelaile.net.cn`
- 开发域常量：`dev.chelaile.net.cn`（已标记 Deprecated）
- URL 拼接：`DomainConfig.toUrlString()` → `https://api.chelaile.net.cn<path>?<query>`

## 3. 请求参数

### 3.1 线路详情 / 刷新车辆

`LineDetailRequest.queryGrayLineDetail()` 组装，`queryGrayBusesDetail()` 类似：

| 参数 | 含义 |
|---|---|
| `lineId` | 线路 ID；为空时改用 `lineNo` + `lineName` + `direction` |
| `targetOrder` | 等车站的站点序号 |
| `specialTargetOrder` | 站点显示序号 |
| `stationName` / `nextStationName` | 当前站与下一站名称（序号不可用时使用） |
| `stationId` / `physicalStId` | 站点 ID / 物理站台 ID |
| `nextStationId` / `nextPhysicalStId` | 下一站 ID |
| `targetStationLng` / `targetStationLat` | 目标站坐标（刷新接口） |
| `lng` / `lat` / `gpstype` | 用户当前位置与坐标系 |
| `filter` | 车辆筛选（刷新接口） |
| `direction` | 方向 |
| `isNewLineDetail` | 固定为 1 |
| `hpGnv` | 固定为 1（`putHpGnv`） |
| `cryptoSign` | 本类实现中返回空串 |
| `sign` | 公共签名参数，见 3.3 |

`/bus/stop!encryptedNearPhysicalStns.action` 在 URL 白名单中，会保留客户端 `lat/lng/gpstype` 参数；其它接口在位置未发生明显变化时会移除这些参数，改传 `encLoc`。

### 3.2 位置加密

`ToUrlStringUtil.encryptLocationInfo()`：

```text
encLoc = AES-GCM( "lat=<纬度>&lng=<经度>&gpstype=GCJ", AKey.KEY )
```

经纬度先转成 GCJ-02。与上次请求的位置距离小于服务端配置的 `getLocateNotifyDistance()` 时不带坐标参数。

### 3.3 签名与时间戳

公共参数来自 `FireflyApp.getAppParams()`：`AppLaunchSession`、`KpiFixedConfig`（`imei`、`imsi`、`mac`、`udid`、`v`、`vc` 等）、`KpiVariableConfig`（`cityId`、`cityName`、`nw`、`geo_provider`、`gps_ts` 等）、用户信息、`ServerConfig` 和 `sign`。

请求有三层签名：

1. **`sign`（`DefaultRequestSigner.getSign()`）**
   ```text
   sign = Base64( 3DES-ECB/PKCS5Padding( currentTimeMillis, 3DES_KEY ) )
   ```
   `3DES_KEY` 在 `sdk/core/DefaultRequestSigner.java` 中。

2. **`cryptoSignStr`（`CryptoUtil.getUrl()`）**
   ```text
   str = "action=<URL encoded path>"
       + "&udid=<udid>"
       + "&accountId=<accountId>"
       + "&timeStamp=<毫秒时间戳>"
       + CRYPTO_OFFSET
   cryptoSignStr = MD5(str, UTF-8)
   ```
   同时追加 `timeStamp`。`CRYPTO_OFFSET` 在 `sdk/query/data/source/CryptoUtil.java` 中。

3. **`cryptoSign`（`BusRequest.queryTimeTable()`）**
   ```text
   cryptoSign = MD5( lowercase( 全部参数拼接串 ) + "#qwihrnbtmj" )
   ```
   注意：`LineDetailRequest.getCryptSign()` 当前直接返回空串，线路详情接口未启用该签名。

参数拼接顺序为 `OptionalParam` 内部 Map 的插入顺序，`ParamProviderUtil.inflateQueries()` 使用 `URLEncoder.encode(..., "UTF-8")`。

## 4. 响应处理

`BaseRequest.parseNetworkResponse()` → `ResponseUtil.parseNetworkResponse()`。响应按响应头 `cllEncType` 解码：

| 编码 | 处理 |
|---|---|
| `aes-gcm-v2` | AES-GCM 解密后 gzip 解压 |
| `aes-gcm-v2-gzip-base64` | Base64 → AES-GCM → gzip |
| 其它 | 按编码头做 Base64 和 / 或 gzip 处理 |

响应体可能带包裹：`**YGKJ{"jsonr": ... }YGKJ##`，`pruneRespJsonr()` 会去掉前后缀。

若 `data.encryptResult` 存在，则用 AES-GCM 解密该字段，并把明文包成标准 `{"data": ..., "status": ..., "errmsg": ...}` 结构。密钥位于 `sdk/core/ResponseUtil.java` 与 `sdk/core/AKey.java`。

Gson 要求外层状态字段 `status` 等于 `"00"` 才算成功（`ResponseUtil.isStatusAvailable()`）。

## 6. 距离与到站时间的计算

1. **还有几站**（`QueryApiUtil.getStnDistance()`、`DistanceRuleUtil.getStnDistanceDesc()`）：
   ```text
   从 bus.drawOrder 数到 target.drawOrder，跳过 isSpecial() 的站
   ```
2. **还有多少米**（`QueryApiUtil.getCurrentBusToTargetStationDistance()`）：
   ```text
   bus.distanceToCurrentStation + Σ 中间各站的 distanceToSp
   ```
3. **还有几分钟**：直接使用 `travels[0].travelTime`，单位为秒；长时间跨天时显示时间点或「明天」（`TimeRuleUtil`）。
4. **文案规则**（`StnValue`、`BusInfoViewA`）：
   - 剩余站数为 0 且 `state == 1` → 已到站；
   - 剩余时间为 0 且 `travelTime <= STN_ARRIVAL_SOON_TIME` → 即将到站；
   - 阈值本地默认 180 秒，服务端可配置；
   - 服务端还可直接下发 `busStatusDesc` 覆盖客户端文案。
5. **刷新**（`SettingRefreshTimer`、`LineDetailPresenterImpl`）：
   - 默认间隔 30 秒；
   - 响应字段 `refreshInterval`（秒）通过 `changeInterval()` 覆盖；
   - 线路详情重试超时取 `AppStatusData.getMainNetTimeOut()`，默认 6000ms，重试 1 次。

## 7. 典型请求流程

```text
选择线路与等车站
  → 组装 lineId / targetOrder / stationId / 位置 / 公共参数
  → sign = 3DES(时间戳)
  → encLoc = AES-GCM(经纬度)
  → cryptoSignStr = MD5(action + udid + accountId + timeStamp + 盐)
  → GET https://api.chelaile.net.cn/bus/line!encNLineDetail.action?...
  → 按 cllEncType 解密响应、拆包裹、必要时解密 encryptResult
  → Gson 反序列化为 LineDetailGrayData
  → 客户端计算站数与米数，展示 travelTime
  → 定时器到点请求 encRefreshLineDetail
```

## 8. 说明与边界

- 未对线上接口发起请求，上述字段与算法均为静态分析结果。
- 盐值、3DES / AES-GCM 密钥是 App 内置常量，具体字面值请查看对应的反编译文件；本文不复制密钥。
- 服务端如何汇聚车辆 GPS、预测算法细节、接口频次限制均不可从 APK 确认。
- 若要自行请求接口，需要完整复现签名与响应解密；请遵守服务条款，控制请求频率。
