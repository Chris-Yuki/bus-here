# 「车来了」App 接口分析

> 分析对象：`车来了.apk`（versionName **7.6.9** / versionCode **437**）。
> 结论来源：静态反编译（`jadx_c6/`、`jadx_out/`）+ **2026-11-26 低频线上实测**（共 9 次请求，间隔 30–60 秒，全部正常返回，未触发限流）。
> 密钥、盐值均为 App 内置常量，本文只说明位置与算法，不复制字面值。

## 0. 实测摘要

测试条件：北京（`cityId=027`），坐标 GCJ `39.9087,116.3975`；线路 `010-1-0`（1 路，四惠枢纽站方向），等车站「天安门东」（`order=25`）。

| 接口 | 实测 | 响应形态 | 关键结果 |
|---|---|---|---|
| `/goocity/city/localCity` | 200 / `status=00` | 明文 JSON | 返回北京 `cityId=027` |
| `/bus/stop!encryptedHomePage.action` | 200 / `00` | `cllEncType: gab2` | 15 个附近站，`maxInterval=30` |
| `/bus/line!encNLineDetail.action` | 200 / `00` | `data.encryptResult` | 33 站、10 车 |
| `/bus/line!encRefreshLineDetail.action` | 200 / `00` | `data.encryptResult` | 9 车，`travelTime` 随时间递减 |
| `/bus/line!lineRoute.action` | 200 / `00` | 明文 JSON | 570 个轨迹点（WGS） |
| `/bus/line!busList.action` | 200 / `00` | `data.encryptResult` | 8 条发车记录 |
| `/bus/query!encryptedNSearch.action` | 200 / `00` | `data.encryptResult` | 关键词「天安门」：2 站、9 POI |
| `/bus/query!encryptedSearchMore.action` | 200 / `00` | `data.encryptResult` | 简单参数下结果为空（见 8.8） |

**未实测**：收藏（`/bus/fav!*`）、到站提醒（`/bus/reminder!*`）、留言板、地铁、换乘、行程上报、城市配置等写接口/账号接口。这类接口大概率需要登录态，本文不做结论。

## 1. 总体架构

App 本身不接收公交车定位信号，而是向服务端查询：

1. 用户选定线路与等车站，App 发送 `lineId + targetOrder + 本机位置 + 公共参数`。
2. 服务端返回该线路上每辆车的实时状态（站点序号、经纬度、预计到站时间）。
3. App 解密响应，在客户端计算「还有几站」「还有多少米」，并展示服务端给出的「还有几分钟」。
4. 默认每 30 秒轮询刷新（实测首页 `maxInterval=30`），服务端可通过 `refreshInterval` 字段覆盖。

公交车定位的上游来源（车载 GPS、公交公司调度系统等）属于服务端内部，无法从 APK 中确认。

- 主域：`https://api.chelaile.net.cn`
- 备域：`https://cdn.api.chelaile.net.cn`
- 开发域常量：`dev.chelaile.net.cn`（已标记 Deprecated）
- URL 拼接：`DomainConfig.toUrlString()` → `https://api.chelaile.net.cn<path>?<query>`

## 3. 请求参数

### 3.1 线路详情 / 刷新车辆

`LineDetailRequest.queryGrayLineDetail()` 组装，`queryGrayBusesDetail()` 类似：

| 参数 | 含义 |
|---|---|
| `lineId` | 线路 ID；为空时改用 `lineNo` + `lineName` + `direction` |
| `targetOrder` | 等车站的站点序号 |
| `specialTargetOrder` | 站点显示序号 |
| `stationName` / `nextStationName` | 当前站与下一站名称（序号不可用时使用） |
| `stationId` / `physicalStId` | 站点 ID / 物理站台 ID |
| `nextStationId` / `nextPhysicalStId` | 下一站 ID |
| `targetStationLng` / `targetStationLat` | 目标站坐标（刷新接口） |
| `lng` / `lat` / `gpstype` | 用户当前位置与坐标系 |
| `filter` | 车辆筛选（刷新接口） |
| `direction` | 方向 |
| `isNewLineDetail` | 固定为 1 |
| `hpGnv` | 固定为 1（`putHpGnv`） |
| `cryptoSign` | 线路详情为空串；时刻表使用真实签名（见 3.3） |
| `sign` | 公共签名参数，见 3.3 |
| `encrypt` | 固定为 1（`CommonInterceptor` 给所有请求追加） |
| `encLoc` | AES-GCM 加密后的经纬度，见 3.2 |

`/bus/stop!encryptedNearPhysicalStns.action` 在 URL 白名单中，会保留客户端 `lat/lng/gpstype` 参数；其它接口在位置未发生明显变化时会移除这些参数，改传 `encLoc`。

### 3.2 位置加密

`ToUrlStringUtil.encryptLocationInfo()`：

```text
encLoc = AES-GCM( "lat=<纬度>&lng=<经度>&gpstype=gcj", AKey.KEY )
```

- 经纬度先转成 GCJ-02，`gpstype` 取 `GeoType.GCJ`（小写 `gcj`）。
- GCM 包裹格式：12 字节随机 nonce + 密文 + 16 字节 tag，整体 Base64。
- 与上次请求的位置距离小于服务端配置的 `getLocateNotifyDistance()` 时不带坐标参数。

### 3.3 签名与时间戳

公共参数来自 `FireflyApp.getAppParams()`，实测服务端接受的字段包括：

```text
s=android, sv, v=7.6.9, vc=437, udid, last_src, first_src, deviceType,
astate, sstate, romVersion, fontType, supportPersonalise, supportContentPersonalise,
enableAccessibility, appInstallTime, localIdCreateTime, mobile_time,
push_open, system_push_open, lchsrc, wifi_open, nw, language,
paramsMakeUp=is, sign, appStartId, zxAid, phoneName,
hpGnv=1, homePreArrivalTimeType=0, preArrivalTimeType=1,
busSizeBeforeWaitOrderGray=1, lineDetailDataBreakType=1, timeTableType=1,
favGrayForAI=1, supportFavDirection=0
```

> 注：7.6.9 版本不再携带 `imei/imsi/mac`；`cityId` 是字符串（北京为 `027`）。

请求有三层签名：

1. **`sign`（`DefaultRequestSigner.getSign()`）** — 实测有效
   ```text
   sign = Base64( 3DES-ECB/PKCS5Padding( currentTimeMillis, 24 字节 3DES_KEY ) )
   ```
   `3DES_KEY` 在 `sdk/core/DefaultRequestSigner.java`。

2. **`cryptoSignStr`（`CryptoUtil.getUrl()`）** — 只对白名单接口追加
   ```text
   str = "action=<URL encoded path>"
       + "&udid=<udid>"
       + "&accountId=<accountId>"   // 为空时整段省略
       + "&timeStamp=<毫秒时间戳>"
       + CRYPTO_OFFSET
   cryptoSignStr = MD5(str, UTF-8)
   ```
   同时向 URL 追加 `timeStamp`。
   当前版本白名单（`InterceptorsKt.NEED_CRYPTO_URLS`）只有：
   `/bus/stop!encryptedHomePage.action`、`/bus/subway_v2/lineDetail`。
   **线路详情、刷新、搜索、轨迹、时刻表都不追加 `cryptoSignStr`**；时刻表会自行追加（见下）。
   `CRYPTO_OFFSET` 在 `sdk/query/data/source/CryptoUtil.java`。

3. **`cryptoSign`（`BusRequest.queryTimeTable()`）** — 实测时刻表接口接受
   ```text
   cryptoSign = MD5( lowercase( 全部参数拼接串 ) + "#qwihrnbtmj" )
   ```
   拼接串使用 `URLEncoder.encode(..., "UTF-8")`，即 key=value 用 `&` 连接后整体转小写。
   `LineDetailRequest.getCryptSign()` 当前直接返回空串，线路详情接口未启用该签名。

参数拼接顺序为 `OptionalParam` 内部 `ConcurrentHashMap` 的遍历顺序；实测按稳定插入顺序构造即可通过时刻表校验，服务端对顺序并不严格。

### 3.4 请求形态

- 全部为 `GET`，参数全部放 query。
- 请求头未做特殊要求；OkHttp 默认 `User-Agent` 即可，实测 `okhttp/4.12.0` 正常。
- 金额/统计类参数可能被服务端忽略，不影响实时数据。

## 4. 响应处理

`BaseRequest.parseNetworkResponse()` → `ResponseUtil.parseNetworkResponse()`。

**更正**：`cllEncType` 的实际取值是 `ga2` / `gab2`；`aes-gcm-v2` 不是响应头值，而是 `data.encryptResult` 字段内部使用的协议名。

| 响应形态 | 判定 | 处理 |
|---|---|---|
| `cllEncType: gab2` | 响应头 | Base64 → AES-GCM(12B nonce + tag) → gzip |
| `cllEncType: ga2` | 响应头 | AES-GCM → gzip |
| `data.encryptResult` 字符串 | body 内字段 | Base64 → AES-GCM（协议名 `aes-gcm-v2`）→ 明文 JSON |
| 明文 | 无头、无 `encryptResult` | 直接 JSON，可能带 `**YGKJ` 包裹 |

要点：

- AES-GCM 密钥为 32 字节（`AKey.KEY`），解密失败时会尝试 `AKey.KEY_BEFORE` 回退。
- 实测同一批接口存在两种加密模式：首页走整包 `gab2`；线路详情/刷新/时刻表/搜索走 `data.encryptResult`；轨迹接口直接明文。
- 即使响应是 `text/html`，body 仍是加密 JSON；HTTP 层 `Content-Encoding: gzip` 与应用层 gzip 可能叠加。
- 响应体可能带包裹：`**YGKJ{"jsonr": ... }YGKJ##`，`pruneRespJsonr()` 会去掉前后缀。
- 若 `data.encryptResult` 存在，解密后的明文被包成标准结构：
  ```json
  { "data": <解密后的 JSON>, "status": "00", "errmsg": "...", "subCode": "...", "subMsg": "..." }
  ```
- Gson 要求外层状态字段 `status` 等于 `"00"` 才算成功（`ResponseUtil.isStatusAvailable()`）。

## 6. 距离与到站时间的计算

1. **还有几站**（`QueryApiUtil.getStnDistance()`、`DistanceRuleUtil.getStnDistanceDesc()`）：
   ```text
   从 bus.order 数到 targetOrder，跳过 isSpecial() 的站
   ```
2. **还有多少米**（`QueryApiUtil.getCurrentBusToTargetStationDistance()`）：
   ```text
   bus.distanceToCurrentStation + Σ 中间各站的 distanceToSp
   ```
3. **还有几分钟**：直接使用 `travels[0].travelTime`，单位为秒；长时间跨天时显示时间点或「明天」（`TimeRuleUtil`）。
4. **文案规则**（`StnValue`、`BusInfoViewA`）：
   - 剩余站数为 0 且 `state == 1` → 已到站；
   - 剩余时间为 0 且 `travelTime <= STN_ARRIVAL_SOON_TIME` → 即将到站；
   - 阈值本地默认 180 秒，服务端可配置；
   - 服务端还可直接下发 `busStatusDesc` 覆盖客户端文案。
5. **刷新**（`SettingRefreshTimer`、`LineDetailPresenterImpl`）：
   - 默认间隔 30 秒（实测首页 `maxInterval=30`）；
   - 响应字段 `refreshInterval`（秒）通过 `changeInterval()` 覆盖；实测该线路返回 0，表示沿用默认；
   - 线路详情重试超时取 `AppStatusData.getMainNetTimeOut()`，默认 6000ms，重试 1 次。

## 7. 典型请求流程

```text
选择线路与等车站
  → 组装 lineId / targetOrder / stationId / 位置 / 公共参数
  → sign = 3DES(时间戳)
  → encLoc = AES-GCM(经纬度)
  → 需要时追加 cryptoSignStr / cryptoSign
  → GET https://api.chelaile.net.cn/bus/line!encNLineDetail.action?...
  → 按 cllEncType 或 data.encryptResult 解密
  → 反序列化
  → 客户端计算站数与米数，展示 travelTime
  → 定时器到点请求 encRefreshLineDetail
```

## 8. 实测接口明细

### 8.1 城市定位

```text
GET /goocity/city/localCity?lat=39.9087&lng=116.3975&gpstype=gcj
```

明文 JSON。关键字段：

```json
{"status":"00","data":{"localCity":{
  "cityId":"027","cityName":"北京","cityVersion":2,
  "lat":39.9223,"lng":116.383027,"gpstype":"wgs"
},"flushInterval":35000,"state":1}}
```

`cityId` 为字符串；`flushInterval` 可作为城市配置刷新参考。

### 8.2 首页附近站点

```text
GET /bus/stop!encryptedHomePage.action?cityId=027&type=5&lat=..&lng=..&gpstype=gcj
    &favoriteGray=1&lineSortType=1&hist=&encrypt=1[&timeStamp=..&cryptoSignStr=..]
```

响应头 `cllEncType: gab2`。关键字段：

- `maxInterval=30`：推荐轮询秒数。
- `nearSts[]`：附近站，含 `sId`、`physicalStId`、`distance`、`firstLineId`。
- `nearSts[].lines[].line`：线路信息（`lineId/lineNo/name/direction/endSn`）。
- `nearSts[].lines[].targetStation`：该线路在本站的 `order/sId/sn`，可直接用于线路详情。
- `nearSts[].lines[].stnStates[]`：该站实时到站（`busId/travelTime/arrivalTime/state/value`），首页即可直接展示。

### 8.3 线路详情

```text
GET /bus/line!encNLineDetail.action?lineId=010-1-0&targetOrder=25&specialTargetOrder=25
    &stationId=010-8017&physicalStId=...&isNewLineDetail=1&cryptoSign=&encrypt=1
```

响应为 `data.encryptResult`。**结构更正**：解密后不是扁平的 `LineDetailGrayData`，而是模块化页面：

```json
{
  "showStyle": 3,
  "modules": [
    { "type": 1, "data": { "line": {...}, "stations": [33 项], "buses": [10 项],
                           "targetOrder": 25, "specialTargetOrder": 25,
                           "refreshInterval": 0, "traPath": "..." } },
    { "type": 20, "data": { "days": ..., "title": ... } },
    ...
  ]
}
```

车辆、站点都在 `modules` 中 `type=1` 的 `data` 下。站点含 `order/sId/physicalStId/sn/lat/lng/wgsLat/wgsLng/distanceToSp`。

### 8.4 刷新车辆

```text
GET /bus/line!encRefreshLineDetail.action?lineId=..&targetOrder=25&specialTargetOrder=25
    &stationName=..&lineName=..&lineNo=..&direction=0
    &targetStationLng=..&targetStationLat=..&physicalStId=..&stationId=..
    &filter=0&isNewLineDetail=1&cryptoSign=&encrypt=1
```

响应同样为 `data.encryptResult` + `modules`。实测返回 9 辆车，字段 `busId/order/state/travels[].travelTime/distanceToWaitStn` 与详情一致，`travelTime` 随时间递减。适合作为 30 秒轮询接口（只取车辆，不含完整站点列表）。

### 8.5 线路轨迹

```text
GET /bus/line!lineRoute.action?lineId=010-1-0&encrypt=1
```

明文 JSON，`status=00`。结构：

```json
{"data":{
  "gpstype":"wgs",
  "line":{"lineId":"010-1-0","name":"1"},
  "route":[{"distance":0,"lng":116.151779,"lat":39.905507,"stopOrder":1}, ...570 点],
  "stations":[{"order":1,"sId":"010-23888","sn":"首钢园公交场站","lat":..,"lng":..,"gpsType":"wgs","distanceToSp":0}, ...33 站]
}}
```

注意：**轨迹与站点坐标为 WGS**；线路详情里的 `lat/lng` 为 GCJ（另附 `wgsLat/wgsLng`）。地图叠加前需统一坐标系。

### 8.6 时刻表

```text
GET /bus/line!busList.action?lineId=..&targetOrder=25
    &cryptoSign=<MD5(...)>&timeStamp=..&cryptoSignStr=<MD5(...)>&encrypt=1
```

响应为 `data.encryptResult`。关键字段：`targetOrder`、`buses[]`（含 `busId/order` 等）、`line`、`depTimeEntrance`（发车时间 H5 链接）。实测 8 条记录，`cryptoSign` 校验通过。

### 8.7 搜索

```text
GET /bus/query!encryptedNSearch.action?cityId=027&key=天安门&fileds=line,stop&encrypt=1
```

响应为 `data.encryptResult`。结构：

```json
{"status":"00","data":{"highlightKey":"天安门","result":{
  "ordertype":"1,2,3",
  "lineCount":0,"lines":[],
  "stationCount":2,"stations":[{"sId":"010-8017","sn":"天安门东","lat":..,"lng":..,"gpsType":"wgs"}],
  "poiCount":9,"pois":[{"sn":"天安门","lat":..,"lng":..,"address":".."}]
}}}
```

参数 `fileds` 是源码中的真实拼写（不是 `fields`）。实测 `fileds=line,stop` 仍会返回 POI。站点坐标为 WGS，POI 为 GCJ。

### 8.8 搜索更多

```text
GET /bus/query!encryptedSearchMore.action?key=天安门&fileds=line,stop&encrypt=1
```

接口可达、`status=00`，但用上述最简参数返回空结果（`lineCount/stationCount/poiCount` 均为 0）。源码中该接口还带 `supportPhyStn`、`supportGrayTransit`、`lng/lat/gpstype`，推测需要这些参数或用于分页，**暂不作为 App 主搜索接口**。

## 9. 对「公交路线 + 到站提醒」App 的可用性

**结论：做 MVP 够用。**

| App 功能 | 依赖接口 | 可用性 |
|---|---|---|
| 城市定位 / 切换城市 | `localCity`（✅）、`moreCities` | 够用 |
| 附近站点与线路 | `encryptedHomePage`（✅） | 够用，含实时到站 |
| 线路详情 / 站点列表 | `encNLineDetail`（✅） | 够用 |
| 地图折线 | `lineRoute`（✅） | 够用（WGS） |
| 实时刷新 | `encRefreshLineDetail`（✅） | 够用 |
| 搜索 | `encryptedNSearch`（✅） | 够用（`encryptedSearchMore` 参数待补） |
| 时刻表 | `busList`（✅） | 够用 |
| 到站提醒 | 客户端轮询 + 本地通知 | 可行；服务端 `/bus/reminder!*` 未验证且大概率需登录 |
| 收藏 / 历史 | 客户端本地存储 | 可行；云同步需账号体系 |
| 地铁 / 换乘 | `subway*` / `transfer` | 未实测 |

建议：

1. **提醒用客户端轮询**：按 `maxInterval`（30 秒）调用 `encRefreshLineDetail`，读 `travels[0].travelTime`（秒）或 `arrivalTime`，在阈值（如 180 秒 / 1 站）触发本地通知。需要在 Android 上处理后台执行、Doze、电池优化；「杀进程也能提醒」需自建推送后端。
2. **坐标统一**：详情/首页为 GCJ，轨迹与搜索站点为 WGS；落图前统一转换。
3. **限频**：30 秒 × 用户数会放大请求量；务必做本地缓存、单飞（合并同线路并发请求）、随机抖动 1–3 秒、指数退避，并避免在后台高频轮询。
4. **稳定性**：签名/密钥为客户端内置常量，服务端可随时调整；响应是模块化结构，可能增减字段，解析需容错。
5. **合规**：非公开接口，正式发布前需评估服务条款与数据使用范围。

## 10. 说明与边界

- 2026-11-26 已对线上接口做过低频实测（9 次请求，30–60 秒间隔），未触发限流；更高频率下的限制未知。
- 盐值、3DES / AES-GCM 密钥是 App 内置常量，具体字面值请查看对应的反编译文件；本文不复制密钥。

- 若自行请求接口，需要完整复现签名与响应解密；请遵守服务条款，控制请求频率。
- 实测样本仅覆盖北京 1 路，其它城市/线路/地铁的字段差异需另行验证。

## 12. 勘误与补充（2026-11-27 · APK 7.6.9 dex 静态核验）

以下结论来自 `原产品车来了.apk` 的 `apkanalyzer dex code --class` 反编译，修正正文中的 4 处表述：

1. **§6「还有几分钟：直接使用 `travels[0].travelTime`」需加条件。**
   `StnStateEntity` 自带 `order` 字段，说明 `travels` 可能覆盖多站。取 ETA 应
   `travels.find(t => t.order === targetOrder) || travels[0]`，否则会取到「下一站」而非目标站。

2. **§6.1「跳过 `isSpecial()` 的站」的字段名是 `special`。**
   `StationEntity.type` 的注解为 `@SerializedName("special")`，`isSpecial()` 等价于 `special == 1`。
   §8.3 的 `stations[]` 字段清单应补 `special`（以及 `stationId`、`namesakeStId`、`passLines` 等）。

3. **§6.1 站数起点不是 `bus.order`，而是 `bus.getDrawOrder()`：**
   `getDrawOrder()` = `drawOrder > 0 ? drawOrder : order`。`drawOrder` 不来自 JSON，
   只在 `Parcel` 中读写（客户端为跳站 / 区间车改写显示顺序用）。

4. **§3.1 的 `direction` 不是切换方向的开关。**
   `changeGrayDirection(LineEntity, ...)` 接收的是**另一条 `LineEntity`** 并重新读取其 `lineId`，
   `LineEntity.isDefaultDirection()` 定义为 `direction == -1`，且 `LineEntity` 内含 `otherLines`（对向线路对象）。
   即：**lineId 已唯一标识「线路 + 方向」，direction 只是附带参数**。

补充发现：
- `BusEntity` 无任何拥挤度字段，`crowd` 仅存在于 `R.string.cll_travel_interact_*`（行程互动上报），
  因此「车厢拥挤度」不能作为接口字段使用。
- `BusEntity` 有 `debusStnBusStatusDesc` / `nextStnBusStatusDesc` / `busStatusDesc`，优先展示服务端文案可避免自行拼装。
- `LineEntity.loopMidStopName` 表明存在环线，站序不保证单调递增。

**真机实测补充（2026-11-27，小米 14 / Android 16 / 车来了 7.6.9）：**
- 搜索 `302` 命中线路组 `302路 / S302路 / 3025路`，`§8.7` 的「线路关键词检索」可用。
- 线路详情页单车条目实际展示 `14分钟·4站·2.1千米 / 12:02到达 / 下一站 新洲城市花园`，
  与 `StnStateEntity` + `BusEntity.nextStationName` 完全对应；实测该线路在途仅 1 辆车。

完整评估见 `docs/接口覆盖度评估.md`。
